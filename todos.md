## Rust migration — active architecture priority

The goal is a complete Rust implementation of the current Python capabilities, with cross-platform behavior. **Do not remove, silently weaken, or substitute away any working Python feature or safety invariant.** Treat the current Python engine and the source ZIP as references during migration. New shared GUI/CLI/MCP contracts should be Rust-owned; a narrow validated adapter may call the Python engine only for stages that have not reached parity. FFmpeg and the other media tools remain explicit external processes unless a separate packaging decision changes that.
