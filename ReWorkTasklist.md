## Product outcome

Make the normal workflow one clear, resumable library queue:

1. Add individual files and one or more folders.
2. Scan names and technical media details as items enter the queue; discover likely title metadata and poster art in the background.
3. Review matches on poster cards. After files are added, the library is those cards: poster, title, year, current filename, and proposed filename. Each card shows Matching, Suggested, Matched, Local metadata, or No artwork yet while lookup runs. Click a card to pick another poster or correct metadata. A checkbox selects the file, and an Animated checkbox marks that file for the animation encode tune. Streams, memory, HDR, and the output folder stay behind the card. Rename, Metadata-only MKV, and Rebuild act on the selection.
4. Choose a collision-checked rename, a metadata-only MKV copy/remux, or a full HEVC rebuild.
5. Start the batch and follow per-file progress, ETA, output-size estimates, validation, and errors. Recover the queue after an application or computer restart.

The main screen is the work queue and its review state. YouTube preparation is an optional, separate page that can consume selected queue items; YouTube settings and readiness do not appear in the normal rebuild workflow.

Do not promise a universal 99% match rate. Measure precision on a labeled test set; auto-assign only matches meeting a validated high-confidence rule, and route conflicts or weak matches to review.

### Queue implementation status

`desktop/src-tauri/src/media_queue.rs` persists versioned source/scan snapshots, global selection, active source, per-file animation and stream selections, bounded reviewed movie and TV-series metadata, provider-artwork references, episode lists/assignments, selected local movie/series/season artwork paths, and bounded per-file run states in `library-queue.json` beside the app settings profile. Writes are atomic and private on Unix; interrupted scans are identified, corrupt files are preserved with a warning, and changed/missing media is checked on restore. Active operation states (`running`, `scanning`, `renaming`, `remuxing`, `rebuilding`, and `validating`) restore as `interrupted`; later `queued` rows stay queued. The UI persists stage changes without writing every progress tick, counts queue statuses in a stable order, and records organizer renames with mode `organize`. Report rows provide completed, failed, and skipped outcomes; missing report rows are not treated as success. The user must inspect existing output/report data before retrying; there is no automatic resume. Successful organizer renames remap cached queue entries, series roots, episode paths, local-art paths, and related settings so assignments and selections follow the media. The UI can add multiple file/folder sources in sequence, retain earlier scans, refresh or remove one source, and show/reopen reviewed records from the library. Selected local artwork is passed to metadata-only, short-test, and full-rebuild runs; provider artwork still needs explicit local save. The GUI groups ready sources and processes them sequentially, using per-source saved scan settings and deduplicating canonical file paths. `output_targets.rs` provides a bounded, read-only whole-queue path/collision preview shared by the GUI, JSON CLI, and MCP; each engine batch still performs the authoritative write-time preflight. JSON CLI and MCP expose a bounded queue page and exact-path selection update that validates membership and preserves other decisions; synthetic binary smokes verify both. Multi-source CLI/MCP execution and CLI result synchronization are implemented and synthetic-smoke tested. CLI/MCP retries require report/output review and explicit path acknowledgment; there is no automatic resume. Native close/reopen behavior has not been verified.
