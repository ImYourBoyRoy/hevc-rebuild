# HEVC Rebuild Findings — 2026-10-11

## Purpose and scope

This document records the 2026-10-11 code audit and red-team pass over the current HEVC Rebuild worktree. The deepest review was of the shared Python utility boundary in `hevc_rebuild/util.py`, followed through its Python callers, Rust report/transaction code, native media scanning, and the Svelte validation lanes.

The worktree was already substantially dirty before this audit. The findings describe the current source tree; they do not assume that every modified file belongs to one coherent, releasable change. No media was scanned, encoded, replaced, uploaded, or deleted. No package operation or native GUI acceptance test was performed.

## How to read this document

The finding sections below are the current statement. Where an earlier sentence was too wide, it has been narrowed in place. The independent review and the expanded audit are the evidence logs for those statements, including what was re-run and what was not. Start a handoff at **Handoff** at the end. Do not treat an older green entry in `MEMORY.md` or `REVIEW.md` as the current validation result.

Severity meanings:

- **High:** blocks a required validation lane, can corrupt user-visible state, or can violate a core safety invariant under a supported execution path.
- **Medium:** a real correctness, durability, or diagnosability weakness that needs hardening but is conditional or not demonstrated in normal media processing.
- **Low:** maintainability, test-contract, or low-likelihood race debt.
- **Opportunity:** an optimization or product limitation that needs benchmarking or a deliberate product decision before implementation.
- **Verification gap:** not a source defect by itself; the behavior remains unproven in native, packaged, real-media, or target-platform execution.

## Executive assessment

The utility is not release-clean yet, but the earlier audit overstated several items as production failures. The strongest findings are:

1. Report and log identity/writer coordination is unsafe when multiple runs overlap or begin in the same second.
2. The required TypeScript 7 validation lane currently fails with 25 errors.
3. A failed directory open on the Python path is treated as a successful sync. A failed `os.fsync` still raises.
4. Shared parsing helpers accept or propagate malformed values more broadly than their types promise.

The following are not equivalent to confirmed production breakage:

- The `apply_to_args` failure uses an incomplete test argument object; normal `argparse` objects define `embed_artwork`.
- The metadata blacklist tests are stale relative to the current intentional `Movie*Group` default.
- Serial media scanning and the large frontend chunk are optimization opportunities, not proven runtime bottlenecks.
- Ruff and Rust formatting failures are quality-gate failures unless the project’s release/CI policy treats them as blockers.
- Python/Rust parity, native UI, real-media processing, packaged launch, and cross-platform support remain verification gaps rather than automatically being defects.

## Findings and required work

### F-01 — Report path collisions and non-atomic CSV header creation

**Severity:** High when overlapping runs are allowed; Medium for the single-run GUI path.

**Problem**

`configure_logging()` derives both the log and CSV report names from a timestamp with one-second precision. `append_csv()` then performs an existence check followed by an append open:

- `hevc_rebuild/util.py:238-254` — timestamp-based log/report names and root logger setup.
- `hevc_rebuild/util.py:304-309` — `exists()` followed by header/write.
- `desktop/src-tauri/src/reports.rs:148-165` — the native writer repeats the same existence race.
- `desktop/src-tauri/src/mcp_server.rs:935` — a media job is spawned on a worker thread after `insert_job` accepts it. That spawn is not evidence that one MCP server runs two media jobs at once.

Two direct-Python threads calling `append_csv` on one new file reproduced two header rows. The Rust writer has the same existence check and was not the writer in that experiment. Two runs that start in the same wall-clock second, including a second job started after the first has finished, reuse `hevc-rebuild-YYYYMMDD-HHMMSS.csv` and mix rows. Queue sync keeps the first row whose `input` equals a selected path. It does not mark an unrelated path merely because the filename collided. Duplicate headers become data rows to naïve CSV consumers.

**Red-team qualification**

The GUI `claim_job` guard and MCP `insert_job` each block a second media job inside one process while another is active. Separate CLI, GUI, and MCP processes can still start in the same second, and a later job in that same second still appends to the first report. The report path is not globally unique.

**Fix**

1. Allocate a run identifier before logging begins, preferably a UUID or a collision-resistant timestamp/PID/sequence combination.
2. Include the run identifier in both log and report filenames.
3. Make report creation atomic. Use exclusive creation for the first header, or protect the complete append with an inter-process lock.
4. Keep the fixed report schema in one shared contract and reject/record schema mismatches.
5. Add a report writer test with concurrent processes, not only threads.
6. Test queue synchronization against two simultaneous reports and overlapping/non-overlapping selected paths.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/app.py`
- `desktop/src-tauri/src/reports.rs`
- `desktop/src-tauri/src/mcp_server.rs` if run IDs are allocated or propagated there
- New focused tests under `tests/` and Rust tests in `desktop/src-tauri/src/reports.rs`

**Acceptance evidence**

- Two simultaneous runs create different report paths.
- Each report has exactly one header and only its own rows.
- Queue synchronization never marks a path from another job based only on a shared report filename.

### F-02 — Logging handler lifecycle and private-file enforcement

**Severity:** Medium for repeated in-process setup; Medium security hardening for log permissions.

**Problem**

`configure_logging()` calls `root.handlers.clear()` without closing the old file handlers. Repeated setup in one process leaves the previous stream open until it is collected. Engine logs and reports follow the process umask. The explicit private-log rule in `AGENTS.md` covers package and helper setup logs, which already use mode `0600`. Engine run logs are a separate gap.

**Observed behavior**

Calling `configure_logging()` twice in the same second returned the same path, and the previous file handler remained open. This is mainly a lifecycle/test/embedded-call problem because the ordinary CLI path configures logging once per process.

**Fix**

1. Close and flush every existing handler before removing it.
2. Create the log directory with mode `0700` where supported.
3. Create log and report files with mode `0600` where supported.
4. Use a unique run identifier from F-01 rather than relying on timestamps.
5. Add a test that repeatedly configures logging and verifies no old file handler remains open.

**Files to change**

- `hevc_rebuild/util.py`
- New utility tests under `tests/`
- If native-created logs are possible, the corresponding Rust log/report creation code

### F-03 — Non-finite numeric values are accepted or crash formatting

**Severity:** Medium; currently a malformed-input hardening issue, not a demonstrated normal-FFprobe failure.

**Problem**

- `hevc_rebuild/util.py:172-178` — `duration_text(float("nan"))` raises `ValueError`; positive infinity raises `OverflowError`.
- `hevc_rebuild/util.py:181-191` — `safe_float()` returns `nan`, `inf`, and `-inf` instead of normalizing them to `None`.
- `hevc_rebuild/probe.py:327` — duration values flow from external metadata into the profile model.

The direct probe demonstrated both failures. Standard FFprobe output generally uses finite values or null, so this should not be described as an everyday media failure. It is still a weak boundary because external tools, test fixtures, and nonstandard JSON can produce values outside the expected finite domain.

**Fix**

1. Make `safe_float()` return `None` unless `math.isfinite(value)` is true.
2. Make `duration_text()` and `human_bytes()` fail closed to `?`/`unknown` for non-finite values.
3. Validate finite numeric fields before resource planning, progress calculation, report serialization, and native-helper payload creation.
4. Add tests for `nan`, positive infinity, negative infinity, strings containing those values, and nulls.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/probe.py`
- `hevc_rebuild/model.py` if model-level finite constraints are added
- Tests for utility, probe, progress, and report serialization

### F-04 — JSON helper contracts are weaker than their annotations

**Severity:** Low to Medium.

**Problem**

`run_json()` is annotated as returning `dict[str, Any]`, but it only catches JSON syntax errors. It accepts valid JSON arrays, strings, numbers, and nulls. A direct probe confirmed that `run_json(["/usr/bin/printf", "[]"])` returns a list despite the annotation.

Current FFprobe and MKVToolNix callers normally return objects, so this is primarily a poor failure boundary rather than a current production incident.

**Fix**

1. Rename the generic helper to reflect that it returns arbitrary JSON, or enforce an object result.
2. Add a typed `run_json_object()` helper for callers using `.get()`.
3. Validate required top-level keys at each external-tool boundary and include the executable/path in the error.
4. Add malformed-shape tests for `[]`, `null`, scalar JSON, and missing required keys.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/probe.py`
- `hevc_rebuild/metadata.py`
- `hevc_rebuild/deps.py`
- `hevc_rebuild/environment.py`
- New focused tests under `tests/`

### F-05 — Subprocess timeout, descendant cleanup, and stderr draining

**Severity:** Medium; higher for helper failures or hostile/very verbose tools.

**Problem**

- `native_json_action()` allows `timeout=None` for long HDR operations and captures output without a size limit.
- `run()` passes `TimeoutExpired` and many `OSError` cases through without consistent command-context wrapping.
- `drain_pipe()` appends every stderr line to an unbounded list.
- `_NativeRuntimeGuard.close()` closes stdout/stderr before joining its stderr-drain thread (`hevc_rebuild/encode.py:565-569`).

The existing native Rust media scanner has capped output and explicit child killing, so the Python utility is less defensive than the native path. The earlier audit correctly identified a design gap but did not prove that ordinary FFmpeg output currently exhausts memory or loses diagnostics.

**Fix**

1. Use a bounded `deque` or a byte/line budget for retained stderr.
2. Join drain threads before closing their streams, and propagate drain errors when practical.
3. Start helper process groups/session boundaries and terminate the group on timeout or cancellation.
4. Preserve a hard upper bound even for operations whose normal timeout scales with media length.
5. Wrap `TimeoutExpired`, `FileNotFoundError`, and permission failures in `ExternalCommandError`/`RebuildError` with command and phase context.
6. Add tests for a helper that sleeps, spawns a child, emits large stderr, and exits after the parent timeout.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/encode.py`
- `hevc_rebuild/calibration.py`
- `hevc_rebuild/hdr.py`
- `hevc_rebuild/app.py`
- Tests for child lifecycle and bounded diagnostics

### F-06 — Python configuration helper assumes a full argparse namespace

**Severity:** Low to Medium; test/API robustness issue, not a normal CLI failure.

**Problem**

`hevc_rebuild/config.py:445` directly reads `args.embed_artwork`. The production parser defines that field, but a partial namespace or compatibility caller does not have to. The current unit test exposes this with `SimpleNamespace`.

**Fix**

Use the same defensive pattern as nearby fields, for example `current = getattr(args, "embed_artwork", None)`, then apply the configured default. Decide whether `apply_to_args()` should formally require a parser namespace; if so, encode that contract in tests and typing instead of silently accepting partial objects.

**Files to change**

- `hevc_rebuild/config.py`
- `tests/test_config_content.py`

### F-07 — Source/test contract drift around metadata defaults and helper paths

**Severity:** Low to Medium.

**Problem**

The current source intentionally seeds `metadata.text_blacklist` with `Movie*Group`, while two tests still expect an empty list. The direct metadata toolchain test is also affected by the host’s managed `hdr10plus_tool` path despite mocking `which()`.

This is not evidence that `Movie*Group` is wrong. It is evidence that source, tests, and environment isolation are out of sync.

2. Update tests to assert that intended behavior.
3. Isolate tool discovery tests from the user’s real managed tool cache and home directory.
4. Inject explicit tool roots or patch the managed-data resolver, not only `PATH` lookup.

### F-08 — Required TypeScript 7 validation lane is failing

**Severity:** High release-validation blocker.

**Problem**

`pnpm check` passes, but `pnpm check:tsgo` reports 25 errors in `desktop/src/routes/+page.svelte`. The first two say that `LibraryCrumb` and `LibraryPosterCard` are not exported from the Svelte module under TypeScript 7. Many later callback parameters become implicit `any` because event/prop types are no longer inferred.

The interfaces exist in `desktop/src/lib/LibraryPosterGrid.svelte`, so this is probably a compiler/type-generation compatibility boundary rather than missing declarations.

**Fix**

1. Move shared interfaces and event payload types out of `.svelte` files into a normal `.ts` module, likely under `desktop/src/lib/` or the existing shared type module.
2. Import those types from the normal TypeScript module in `+page.svelte` and the component.
3. Explicitly type component callback props/events where inference remains unstable under TS7.
4. Run both checker lanes after each change; do not weaken `noImplicitAny` to hide the errors.

**Files to change**

- `desktop/src/routes/+page.svelte`
- `desktop/src/lib/LibraryPosterGrid.svelte`
- Related component prop/event declarations producing the implicit-`any` cascade
- `desktop/src/lib/types.ts` or a new shared type module
- `desktop/tsconfig.json` only if a targeted compatibility adjustment is justified

**Acceptance evidence**

- `pnpm check` — zero errors and warnings.
- `pnpm check:tsgo` — zero errors and warnings.
- `pnpm build` — successful production build.

### F-09 — Filesystem durability errors are silently downgraded

**Severity:** Medium on supported Linux; lower outside the supported platform set.

**Problem**

`hevc_rebuild/util.py:216-224` returns without error when `os.open` of the directory fails, including a missing directory. `os.fsync` errors propagate, and `commit_transaction` re-raises them. The Rust transaction returns directory-sync errors on Linux and makes directory syncing a no-op on non-Unix platforms (`desktop/src-tauri/src/transactions.rs:311-314`).

The normal Linux path can sync successfully. The defect is the false success when the directory cannot be opened, not a swallowed `fsync`.

**Fix**

1. Raise a clear error when opening a directory for sync fails on Linux. Keep `os.fsync` failures as errors; they already propagate.
2. Distinguish “operation completed” from “durability confirmed” in user/report messaging.
3. Keep the non-Unix behavior explicit in documentation and release claims.
4. Add tests using injected sync functions/failure mocks.
5. For the organizer, add a persistent journal or recovery manifest if crash recovery is a product requirement; in-memory rollback alone cannot recover a process or power loss.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/app.py`
- `desktop/src-tauri/src/transactions.rs`
- `desktop/src-tauri/src/library_organizer.rs`
- Transaction and durability tests

### F-10 — Backup path selection has a check-then-use race

**Severity:** Low to Medium; relevant only when another process touches the same source/backup directory.

**Problem**

`unique_backup()` selects the first path for which `exists()` is false. Direct Python, when `HEVC_REBUILD_NATIVE_HELPER` is unset, later calls `os.replace` for the backup and for `final_output` (`app.py:744-755`). A path created in that window can be overwritten.

Studio GUI, CLI, and MCP set that helper when `current_exe` succeeds. Those commits use `renameat2(RENAME_NOREPLACE)` and fail the commit if the destination appears. If `current_exe` fails, the same process falls through to `os.replace`. This is not a demonstrated routine GUI failure.

**Fix**

1. Reserve the backup name atomically before moving the source, or use an atomic no-replace primitive.
2. Revalidate the destination immediately before commit.
3. Add a race test with a competing creator.

**Files to change**

- `hevc_rebuild/util.py`
- `hevc_rebuild/app.py`
- Python transaction tests

### F-11 — Native media scan is serial and recomputes expensive derived data

**Severity:** Opportunity; no benchmark currently proves user-visible slowness.

**Problem**

`desktop/src-tauri/src/media_scan.rs:135-235` processes files serially. Each file may invoke FFprobe and MediaInfo (`:678-720`), then eagerly computes rebuild forecasts plus three YouTube resolution forecasts. The tool polling loop sleeps for 40 ms (`:1128`). The scan is capped at 10,000 files.

Serial behavior may be intentional to avoid saturating CPU, disks, or media tools. It should not be changed blindly.

**Fix after measurement**

1. Add scan timing telemetry broken down by discovery, FFprobe, MediaInfo, and forecast calculation.
2. Cache profiles by canonical path, size, mtime, tool versions, and relevant settings.
3. Consider a small bounded worker pool, probably 2–4 workers, with cancellation and progress accounting.
4. Compute YouTube forecasts lazily when the YouTube workflow is opened or explicitly requested.
5. Preserve bounded output and tool resource limits.

**Files to change**

- `desktop/src-tauri/src/media_scan.rs`
- `desktop/src-tauri/src/media_queue.rs` or a dedicated scan-cache module
- `desktop/src-tauri/src/settings.rs` if cache policy becomes configurable
- Native scan benchmarks/tests

### F-12 — Rust formatting, dead code, and lint cleanliness

**Severity:** Low unless enforced as a release gate.

**Problem**

The current source passed Rust unit tests and `cargo check`, but `cargo fmt --all -- --check` reported formatting differences and Rust emitted four dead-code warnings. Ruff reported 176 issues in the available environment, many involving imports, logging style, and unused code.

These are not evidence that the media engine is functionally broken. They increase maintenance cost and can hide real warnings.

**Fix**

1. Decide whether the repository requires whole-tree formatting in CI.
2. Apply formatting only after separating the user’s unrelated dirty changes or after explicit approval, because formatting many dirty files creates a large diff.
3. Remove or wire up genuinely unused functions/imports.
4. Pin/document the lint tool used by CI so “Ruff unavailable” and “Ruff found issues” are not conflated.

**Files to change**

- Affected Rust files reported by `cargo fmt --check`
- Affected Python files reported by Ruff
- CI/tool configuration if lint is intended to be mandatory

### F-13 — Python/Rust parity remains an architecture risk

**Severity:** Medium architecture risk; not a single failing function.

**Problem**

The migration intentionally splits behavior between Rust and Python. Python still owns orchestration, direct CLI behavior, report values, remaining Matroska work, and fallback paths. Rust owns increasing portions of scanning, planning, supervision, validation, transactions, and reports.

The risk is behavioral drift: a feature can pass a Rust unit test while direct Python and app-launched paths differ in defaults, errors, reports, or safety checks.

**Fix**

1. Maintain parity fixtures for settings, stream selection, HDR/Dolby Vision decisions, reports, and transaction outcomes.
2. Run the same fixture through direct Python and Rust-launched compatibility paths.
3. Treat “Rust tests pass” and “Python tests pass” as separate evidence, not interchangeable proof.
4. Keep `RUST_MIGRATION.md` synchronized with actual ownership and open gaps.

**Files to change**

- `RUST_MIGRATION.md`
- `AGENTS.md`
- `hevc_rebuild/app.py`, `config.py`, `probe.py`, `encode.py`, `validate.py`
- Corresponding `desktop/src-tauri/src/*.rs` modules
- Cross-path fixtures/tests

### F-15 — YouTube HDR10+ handling is an explicit product limitation

**Severity:** Product limitation, not an undisclosed defect.

The YouTube exporter intentionally does not carry HDR10+ dynamic metadata through. The source is skipped by default, and an explicit per-file opt-in records the loss. That is a defensible fail-closed policy, but it is not lossless HDR support.

If the product requirement is “preserve HDR10+,” the fix belongs in the exporter and validation path. If the requirement is “produce a compatible YouTube copy with explicit loss consent,” the current behavior should be retained and tested rather than labeled broken.

## Recommended implementation order

### Phase 1 — Release blockers and correctness

1. Resolve the TypeScript 7 type-export/inference failures.
2. Decide the intended metadata blacklist default and repair the stale tests.
3. Isolate tool-discovery tests from the real user cache.
4. Add unique run IDs and atomic/locked report creation.

### Phase 2 — Shared utility hardening

1. Normalize all numeric inputs to finite values.
2. Add typed JSON-object helpers and required-key validation.
3. Bound subprocess diagnostics and fix drain-thread shutdown order.
4. Add process-group cleanup for timeouts/cancellation.
5. Enforce private log/report permissions.

### Phase 3 — Durability and transaction safety

1. Raise when a Linux directory open fails during sync. Do not describe a propagating `os.fsync` error as silent.
2. Make backup-name reservation atomic on the direct Python path. Studio-launched commits already fail closed with `RENAME_NOREPLACE`.
3. Decide whether organizer crash recovery requires a durable journal.
4. Add failure-injection tests for sync, rename, rollback, and power-loss-like interruption boundaries.

### Phase 4 — Measured optimization and parity

1. Benchmark scan phases before changing concurrency.
2. Add profile caching and lazy YouTube forecast calculation where measurements justify it.
3. Run Python/Rust parity fixtures for settings, stream selection, HDR, reports, and transactions.
4. Keep the release documentation explicit about native, packaged, real-media, and platform evidence.

### Red-team of the first review

The first review was too broad in three places:

1. "One MCP server does not overlap media jobs" does not mean a second job gets its own report. `insert_job` rejects a second job only while another job is `queued` or `running`. After the first job finishes, a second job started in that same wall-clock second reuses `hevc-rebuild-YYYYMMDD-HHMMSS.csv`. Queue sync then keeps the first row whose `input` equals a selected path (`mcp_server.rs` around the `rows.iter().find` match). A shared file does not mark unrelated paths. It does apply another job's row when the input path matches.
2. "A crash can drop the last report row" overstated process death. `append_csv` closes the file before returning, and the Rust writer calls `write_all` plus `flush`. Those reach the kernel page cache. Power loss or a kernel crash can still lose the row. An ordinary process exit after a successful append does not.
3. "Desktop commits overwrite" was too narrow a label and too wide a failure. GUI `engine_command`, CLI `standalone_command`, and MCP `execute_media_args` all set `HEVC_REBUILD_NATIVE_HELPER` from `current_exe` when that lookup succeeds. Those commits use `renameat2(RENAME_NOREPLACE)` and fail the commit if the destination appears. `os.replace`, which overwrites, runs only when that variable is absent. The same Python check-then-replace also covers `final_output`, not only the backup path.

These corrections do not remove F-01, F-09, or F-10. They limit the path each one actually takes.

### Findings this audit did not include

**M-01 — Stop-request file follows symlinks. Severity: Medium, and only with another local user.**

GUI, MCP, and `json queue-run` build `hevc-rebuild-stop-{pid}-{nanos}` under the temp directory and pass that path to the engine. The engine treats `Path.exists()` as a stop. `request_stop` and the MCP stop tool call `File::create` when the path does not exist. Neither uses `O_NOFOLLOW` or `O_EXCL`. On a default proc mount, another local user can read the command line, create that name in the sticky temp directory, and point it at a file. A symlink to an existing file makes `exists()` true and stops the run at the next file. A dangling symlink is followed when stop is requested, so the create truncates or creates the target the app user can write. This is not a remote bug, and a single-user session without another account does not exercise it. No exploit was run.

**M-02 — Report append is not power-fail durable. Severity: Low.**

Python `append_csv` and Rust `append_report` do not `fsync` the report file. Rust does `write_all` and `flush`. After a normal return, a process crash should not drop that row. A power loss can still persist a completed media commit and lose the report row, because the commit path syncs the output directory when that sync succeeds and the report path does not sync the CSV. Queue recovery then looks unfinished. That is the safe direction for the media file. It is still a missing durability step next to F-09.

### What stays first

Safety contracts come before the UI split. F-01 is still a unique run id and an atomic header, including for sequential jobs that start in the same second. F-09 should raise when a Linux directory open fails, and should not be described as swallowing `os.fsync` errors. The four Python tests are repaired in that same first session: three are stale contracts, and the metadata toolchain test must be isolated from the user HDR10+ cache. F-08 follows that session. F-10's overwrite wording belongs on the direct Python fallback; studio-launched commits already fail closed. Backend safety work such as M-01, M-02, and F-18 does not wait for the Svelte split. Scan concurrency and formatting stay later. The accepted order at the end of this file is the sequence to follow.

### F-18 — Rust line readers silently discard errors and can spin on repeated errors

**Severity:** Medium.

**Problem**

Clippy flagged repeated `BufRead::lines().flatten()` calls. The pattern appears in `desktop/src-tauri/src/mcp_server.rs` at approximately lines 2313, 2321, 2759, 2764, 2823, and 2828, and in `desktop/src-tauri/src/lib.rs` at approximately lines 1715, 1756, 3663, and 3912.

`flatten()` discards line-read errors. For an iterator that repeatedly returns `Err`, it can also continue indefinitely. Even when the practical failure is only a truncated diagnostic, silently throwing away the error makes process and tool failures harder to explain.

**Fix and files**

Replace the pattern with one of:

- `.map_while(Result::ok)` when termination on the first read error is the intended behavior and the caller records the truncation; or
- an explicit loop that records the I/O error, terminates the child-reader path, and preserves already collected diagnostics.

Add a pipe/read-error test around the shared reader behavior. Apply this in `desktop/src-tauri/src/mcp_server.rs` and `desktop/src-tauri/src/lib.rs`, then rerun Clippy and the Rust test suite.

## Feature-preservation and disposition policy

The goal of this audit is to make the application safer, clearer, more maintainable, and better validated without stripping user-facing capability. No finding authorizes removing a workflow, media mode, metadata behavior, provider, output option, compatibility contract, or safety gate merely because its implementation is large or duplicated.

The implementation rule is:

- **Integrate** fixes for confirmed correctness, safety, durability, type-contract, process-lifecycle, accessibility, and UX problems.
- **Remove only unreachable implementation residue**, such as a redundant import or a crate-private wrapper after its tests call the canonical function. That removal is not a feature cut.
- **Preserve features.** No user-facing workflow, media mode, metadata behavior, provider, output option, compatibility contract, or safety gate is removed to shrink a file or silence a lint.
- **Preserve** compatibility paths when an external caller, saved profile, CLI/MCP contract, or migration requirement may depend on them. If the path is no longer the canonical implementation, make it a thin delegating adapter with tests and a documented retirement condition.
- **Refactor without reducing behavior.** Component, store, CSS, Python, and Rust extraction must preserve existing actions, settings, media policies, provider choices, reports, recovery behavior, and failure boundaries.
- **Do not create artificial calls** to unused helpers just to avoid a lint warning.
