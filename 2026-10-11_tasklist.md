This task list converts the findings into work that another model can execute, verify, and hand off without guessing. It is intentionally conservative about deletion and refactoring: the goal is a safer, clearer, better-tested application, not a smaller application.

## Operating contract

1. Read `AGENTS.md`, `README.md`, `MEMORY.md`, and `2026-10-11_findings.md` before modifying source.
2. Run `git status --short` before every work session. Existing dirty or untracked files belong to the user unless proven otherwise. Do not format, reset, clean, or overwrite unrelated changes.
3. Preserve all user-facing workflows, media modes, metadata behavior, providers, output choices, reports, recovery operations, safety confirmations, CLI/MCP behavior, and compatibility paths.
4. Do not create fake call sites for unused helpers. Remove only a redundant import or unreachable implementation residue after proving the canonical implementation and all references.
5. Preserve compatibility helpers by default. If a helper is no longer canonical, either keep it or make it a tested delegating adapter. Deletion requires a private-symbol search, a compatibility decision, and explicit evidence that no supported caller depends on it.
6. Do not change a product default merely to make a stale test pass. Decide the intended contract, then update the test or product code deliberately and document the decision.
7. Make focused source and documentation edits and review the resulting diff. Do not use broad formatter rewrites on a dirty tree without isolating the diff.
8. Do not process private user media or upload anything. Use synthetic fixtures and explicitly authorized representative files only.
9. Every completed task must record the exact files changed, commands run, result, evidence boundary, and remaining warnings in the progress ledger below.
10. A green source check is not native UI, packaged, real-media, network, cross-platform, or release proof. Label each claim with its evidence type.
11. Do not mark a task complete because a command was attempted. Mark it complete only when its acceptance criteria are met and the result is recorded.
12. Commit boundaries are recommendations. Do not commit unless the user authorizes committing in the current work session; never include unrelated dirty changes.

## Preservation and rollback contract for every implementation task

Every task below preserves Media Library/scan/selection, metadata review, organizer/rename, metadata-only MKV, full rebuild, short test, YouTube preparation, HDR10+/Dolby Vision policy, reports/recovery, tool setup, CLI/MCP, direct Python fallback, native confirmations, and every supported skin/UI surface. The task-specific files listed under each task are the reversible patch boundary; unrelated starting changes remain outside it. Before an implementation slice, its evidence entry must identify the existing entry points and exact affected behavior. `desktop/UI_OWNERSHIP.md` defines UI inputs/outputs/side effects/CSS/test boundaries. This contract specifies preservation expectations, not unexecuted acceptance proof. No compatibility retirement or product-default change is authorized by a warning count.
