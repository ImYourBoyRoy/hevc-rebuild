# Theme, cascade and responsive contract

Verified 2026-10-11 (theme layer added 2026-11-16, see below). The shell's `--theme-*` tokens in `src/styles/app/app-base.css` are canonical. The original root `--ink`, `--panel`, `--green` and related names retain fallback values for standalone markup; inside `.app-shell` they are compatibility aliases to the canonical tokens. Do not introduce another independently maintained palette. The earlier `[data-theme="dark"]` rules provide compatibility selector overrides; the later `.app-shell[data-theme="dark"]` token block controls the full shell palette. Instrument overrides remain in `src/styles/instrument/*.css`, keyed by `html[data-instrument]` and loaded after the application parts. Phosphor, Ion and Breach retain their signal/workflow-art tokens. `styles/type-scale.css` follows both and controls the common reading scale.

`+layout.svelte` loads the application sheet parts (`src/styles/app/*.css`, in order), the instrument parts (`src/styles/instrument/*.css`) and the type-scale sheet; each part stays under the 500-line budget and the concatenation of the parts is the former `app.css` / `instrument.css` byte for byte. Feature components import Home, Library grid and metadata-review sheets or own Svelte styles. Shared run, upload, settings/provider/cache/filter, reports/diagnostics, repair/log and recovery selector families remain explicitly scoped in the application parts; `UI_OWNERSHIP.md` records their consumers. Shared form/button tokens remain shared because several workflows use them. Their cascade has not been flattened or replaced during extraction.

The global viewport floor is 360px at every width. The former 1000px base floor was superseded by a later 360px rule; those contradictory declarations are now one rule. Main/grid children retain `min-width: 0`; large media tables scroll locally. Existing compact shell breakpoints, feature wrapping, dialog viewport bounds and focus styles remain. Acceptance widths are 360, 390, 620, 800, 1024 and 1440. Browser fixtures use the same three global sheets and set the same HTML theme/instrument attributes as the real shell. Browser screenshots prove those fixtures only; native responsive acceptance is recorded separately.

## Theme layer (2026-11-16)

Eight themes ship: Light, Dark, Cinema, OLED, DOS (palette themes) and Phosphor, Ion, Breach (instrument skins). `src/lib/themes.ts` is the frontend registry; `app_preferences.rs` (`APP_THEMES`) validates the same ids. Palette themes extend a base family: the shell publishes `data-theme="dark"` (Cinema, OLED, DOS) so every existing dark/light rule keeps applying, plus `data-palette="<id>"` for the exact theme; instrument skins publish themselves as `data-theme`, `data-palette` and `data-instrument`. The theme parts in `src/styles/themes/*.css` load last: `theme-core.css` (shape, depth, focus and motion tokens, scoped with `html:not([data-instrument])` so it never touches the skins), `theme-light/dark/cinema/oled/dos.css` (token overrides plus a few identity rules; palette parts must override the green-tinted dark rules they inherit) and `theme-phosphor/ion/breach.css` (skin identity; they use `.app-shell.app-shell` to outrank the shared instrument radius rule and own no animated or shared pseudo-element, so the existing Ion and Breach animation is untouched). `pnpm test:theme-contrast` measures WCAG AA contrast of every visible text element in the shell chrome for all eight themes (gradient fills by the worst stop of their bottom layer); it covers the sidebar, header, notice, Home dashboard, the Library screen (poster grid, source rows, scan options, search and the expanded Manage queue file list) and a Reports-style table (header, rows, status tags) for all eight themes, not Run or Settings. About 634 hard-coded hex colours remain in the app/component sheets; they do not follow the theme tokens.

### Motion (2026-11-16)

`theme-motion.css` holds the shared motion tokens (`--ease-out`, `--ease-in-out`, `--ease-standard`, `--dur-fast/base/slow/theme`) and entrances for pages, home cards, library cards (staggered, capped at 24), notices and dialogs; `theme-ambient.css` adds quiet ambient motion for the palette themes (the instrument skins keep their own loops). Rules: animate only `opacity` and `transform` (plus short colour transitions), use `backwards` fill so nothing keeps a transform or stacking context after it ends, fade ambient layers in over about 1.4s so they never pop on, and wrap everything in `prefers-reduced-motion: no-preference`. Switching theme goes through `src/lib/theme-transition.ts`: a whole-page cross-fade with the View Transitions API (class `theme-vt`), a CSS colour-transition window (`theme-fade`) without it, an instant switch under reduced motion, and a guard timeout so a hidden or minimized window still applies the theme (`pnpm test:theme-transition`). Motion has only been verified mechanically (tokens, durations, no stuck state, all browser contracts); how it feels needs a visible window.

### Motion hygiene (2026-11-16)

`pnpm test:motion-hygiene` statically checks every stylesheet and component: no `steps()`, `step-end` or `step-start` in any animation (blinks, strobes and jitter snap instead of flow), no endless animation shorter than 1s except `spin`, no `jitter`, `glitch` or `strobe` keyframes, and every endless non-alternating loop must close seamlessly (identical first and last frame, an invisible reset with opacity 0 at both ends, or an entry in the test's documented periodic list: full rotations, dash offsets equal to a multiple of the dash pattern period via `--dash-period`, background offsets equal to whole stripe periods, bars fully off-screen at both ends). Instrument skins follow the same rules: status dots breathe (`instrument-led`, `breach-beacon`) instead of blinking, sweeps fade in and out at their ends (`hero-sweep`, `ion-slash`, `breach-sweep`, `hud-scan`, `hud-packet`, `hud-check`), readouts cross-fade (`hud-crc`, started half a cycle apart with a negative delay), and the cursor blink is eased. The shared ready-dot breathe applies to palette themes only, so each skin keeps its own indicator. Whether any of this feels good still needs a visible window.

### Skin identities and the canvas backdrop (2026-11-16, owner review of the real window)

The first skin pass only styled Home's classes, so the Library screen looked like a recolour. Each themed skin now styles the shared surface family on every screen (`.library-poster-card`, `.library-source-chip`, `.library-poster-toolbar`, `.library-queue-manager`, `.library-toolbar`, `.search-box`, `.run-console-card`, `.settings-card`, `.metadata-*-card`, `.card-surface`, `.table-card`, `.diagnostic-card`, `.report-item`, `.hardware-card`, `.setup-card`, `.metric-card`, `.mode-card`, `.home-panel`, `.home-action`, `.empty-state`, `.run-mode-picker`), plus posters, headings, controls and notices. When a new screen adds a card class, add it to the lists in `theme-phosphor/ion/breach/cinema/dos.css`.

Identities: Phosphor = toxic acid-green terminal (matrix rain, CRT vignette, terminal-window panels with corner ticks, `//` section markers, scan-gridded posters); Ion = ionised plasma (drifting charged particles with light trails, frosted glass panels with a cyan-to-violet edge, a breathing selected card; the radar arc is removed); Breach = containment alarm (hazard tape under the top bar, a slow searchlight pass, chamfered caution panels with amber edge lines, sparks and eased glitch slices); Cinema = a luxurious old movie palace (crushed crimson velvet as a procedural SVG-lit texture with drapery folds on the walls and sidebar, black lacquer panels piped in gold with art-deco corners, a gold-braided sidebar edge, a tassel fringe swaying under the top bar, theatre curtains that part when the theme starts; behind the content the canvas runs an old reel projector in the bottom-right corner with two turning reels, film marching through the gate and a lens throwing a flickering volumetric beam up and across the screen through depth-layered dust, with an anamorphic streak, old-film scratches, live grain and a cursor spotlight; cards lean toward the pointer via `backdrop/tilt.ts`); DOS = a blue VGA text-mode interface in the spirit of Norton Commander and DOS Edit (white, cyan and yellow on blue, double-line frames, hard block shadows, a gray menu bar, black-on-cyan selection bars, [X] checkboxes, a block cursor, screens that paint in from the top); purely visual, no command line, no key hints, instant hover states. It replaced the short-lived High contrast theme, so there is currently no dedicated accessibility theme (DOS itself keeps AA); a saved `contrast` preference is migrated to Light.

`src/lib/ThemeBackdrop.svelte` draws the animated canvas behind the work area from `src/lib/backdrop/` (`scenes.ts` pure scene state, `engine.ts` frame loop, `random.ts` seeded random). The engine caps frames at about 30 per second, clamps long gaps, pauses while the window is hidden, and under reduced motion paints one still frame. It is decorative (aria-hidden, pointer-events none) and fades in over 900ms. `pnpm test:backdrop` covers the scene rules and the loop. Looping CSS motion added with the skins (film-scroll, hazard-tape) is periodic by construction and registered in the motion-hygiene test. CPU and GPU cost of the canvas has not been profiled.

### Queue, toolbar and table structure (2026-11-16, owner: "the tables are a little rough still")

In the base theme `.library-queue-manager`, `.library-queue-heading`, `.library-source-strip`, `.library-poster-toolbar` and the like are layout wrappers with no padding or frame. The first skin pass put frames on them, so text touched borders, source rows and file rows were boxes inside a box, and Breach's chamfer clipped the search text. Now only true cards live in each skin's surface list; `theme-structure.css` (loaded after every skin) owns the wrappers for Phosphor, Ion, Breach, Cinema and DOS: padded frames, source rows and the Manage queue file list as hairline-divided rows, one compact style for the drag handle and arrow buttons, search and path fields with a single frame (inputs inside a framed field are borderless), real `<table>` header bands and row hover, and status tags with green, amber and red variants. Each skin supplies only `--q-*` tokens; the defaults are in a zero-specificity `:where()` block so a skin's tokens always win. Row actions (Refresh, Remove) and option labels use `--q-accent` and `--q-muted`, never hard-coded colours. The audit also found and fixed real AA misses in shipped themes: the "Include subfolders" label in Light (4.2:1) and the neutral status tag in Light and Dark (hard-coded grey on a hard-coded light ground; now token-based).

### Spacing scale (2026-11-16, owner: "some of the spacing is still not good enough")

Measured on the Library screen the base sheets gave every block its own margin (15px, 14px, 8px; about 12px inside the queue panel), so the page had no rhythm. `theme-core.css` now sets one scale for every theme: `.page-wrap-library` (Library and Home) is a flex column with a 20px gap and its children carry no margins; the queue panel is a flex column with a 16px gap; source rows use a 12px gap; the search box is `min(340px, 100%)` wide with a 240px minimum so its placeholder is never clipped. The framed skins' structure file no longer adds its own margins on top. Sub-lines in a table's last (status) column wrap instead of ending in an ellipsis (`tbody td:last-child .file-cell-sub`); file names and paths in other columns keep their single-line ellipsis. When adding a block to a page, rely on the container gap instead of adding a margin.

### Failures on Reports and the sidebar badge (2026-11-16, owner decision: "latest outcome only")

`failedRows` is no longer every failed row of every saved report. `src/lib/latest-outcomes.ts` (`latestFailureRows`, tested by `pnpm test:latest-outcomes`) keeps a failure only when it is that file's most recent decisive outcome: reports are ordered by `created`; within a report the later row for a file wins; repeated failures of one file count once (the newest); a later `OK`, `METADATA_OK` or `TEST_OK` supersedes an earlier failure; `INFO` (a read-only check), `SKIPPED`, `INTERRUPTED` and unknown statuses never clear a failure; `INTEGRITY_OK` clears `CORRUPT` and `UNREADABLE` but not a failed rebuild; rows without a path are never merged. The Reports banner explains the rule in one line, and the badge uses the same list. Run against the saved development history (30 reports) the old rule showed 6 and the new rule shows 0, because each of those files later succeeded (Doctor Sleep reached TEST_OK, Synthetic_HDR10 reached OK).

### Source chips and framed fields in Light and Dark (2026-11-16, owner screenshot)

A source chip is a pill (`border-radius: 999px`), so it needs padding that follows the curve. Measured before the fix: 4px right padding (Remove ended 5px from the edge), the name button squeezed to 16px by flex layout so "Movies · 4" overflowed into the actions, and 36px arrow buttons. Now (`theme-core.css`, all themes; the skins' structure file overrides the shape only): chip padding `6px 22px 6px 10px` with an 8px gap and a 46px minimum height; the name shrinks with an ellipsis but never below 5.5rem; Refresh and Remove never wrap; arrow and drag buttons are 28px; a chip is at most 100% of the strip, so a very long folder name ellipsizes on its own row instead of overflowing a narrow window (the fixture includes a deliberately long name). Inputs inside a framed field (`.search-box`, `.folder-field`) are transparent and fill the field, so the field is one box (Light and Dark previously painted a second, lighter box inside it).

### Cinema, second review (2026-11-16, owner: "this is not a premium look right now" and "the beam goes one way but the lens points the other")

From the real-window screenshots: the closed curtains were flat hot-raspberry stripes (a repeating-gradient fold layer I had stacked on the texture made perfectly regular bands), the settled screen was heavy near-black boxes with double piping and corner brackets, the "fringe" read as a dotted line, and the projector's lens barrel faced right while its beam left toward the left. Changes: the velvet SVG (`--velvet`, regenerated by tuning `feTurbulence` with vertically stretched base frequencies, diffuse plus specular lighting for ridge sheen, a deep oxblood colour matrix and a fine pile layer) now gives organic gathered pleats; the regular fold stripes are gone; panels are wine-tinted glass with one gold hairline (no double piping, no corner brackets); the dotted fringe is replaced by a scalloped burgundy valance drawn as a vector tile with a gold edge and beads, hanging behind page content (notices are positioned above it, because the top bar's backdrop blur makes it its own stacking layer); the projector is drawn as a lit object (metal gradients, rim light, film wound in turns, lens glow, contact shadow); the beam's layers feather on both edges; and the machine is mirrored so the lens barrel is on its left end and the beam starts at the lens, guarded by a test (`lens.x < body.x`).
